Plainbase 0.7.0 gives the server and offline commands a shared default home at `~/.plainbase`.

## Changed

- **Server state and configuration now default to `$HOME/.plainbase` directly**, including
  `plainbase.conf` and the databases. This applies to ordinary server launches, offline commands
  and Gradle `:server:run`.
- An explicit, nonblank `DATA_DIR` still takes precedence. Containers continue to use their
  explicit `/data` mount. Explicit relative `DATA_DIR` values remain relative to the launch directory.
- Recognizable installations in the old implicit `./data` location now stop with migration guidance
  instead of silently switching to a new database. The check includes theme-only installations and
  refuses to continue if it cannot safely inspect the old location.

## Before upgrading

- **Existing installations should set an explicit absolute `DATA_DIR` before upgrading**, or follow
  the [offline migration runbook](https://github.com/luinstra/plainbase/blob/v0.7.0/docs/operating-plainbase.md#offline-migration-to-the-home-directory)
  to move state to `~/.plainbase`. No state, configuration or documents are migrated automatically.
- `CONTENT_DIR` and relative content-root paths still resolve from the launch directory. Make them
  absolute before changing that directory; the new state default does not relocate your documents.
- Empty or whitespace-only `DATA_DIR` values now fail. If `HOME` is missing, blank, relative or invalid
  when the default is needed, provide a valid absolute `HOME` or an explicit absolute `DATA_DIR`.
- Development launches use the same home-directory default. Set explicit disposable data and content
  paths when testing.
