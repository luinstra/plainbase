Plainbase 0.3.0 adds per-root labels and content filters, speeds up page creation, and strengthens
filesystem access, indexing, recovery and shutdown behavior. These notes cover all changes since 0.2.1;
the previously drafted 0.2.2 release was not published.

## Added

- **Root display names and folder labels.** Use `displayName` to give a root a human-facing name and
  `folderLabels` to label exact relative folder paths, including `.crew`. Labels appear throughout
  navigation, search and proposal review; root names, paths, URLs and page identities stay unchanged.
- **Per-root content filters.** Local roots accept `includes` and `excludes` globs. For example:

  ```hocon
  roots {
    docs {
      path = "/path/to/project"
      displayName = "Project knowledge"
      includes = ["docs/**", ".crew/**"]
      excludes = [".crew/reviews/**"]
      folderLabels { ".crew" = "Planning" }
    }
  }
  ```

  Configuration takes effect after restart. Omitted `includes` preserves the default selection;
  `includes = []` selects no files. Includes select assets as well as Markdown, so a Markdown-only
  pattern needs additional patterns for images and attachments. `**/*.md` does not match top-level
  Markdown files; add `*.md` when needed. Excludes also match ancestors, so excluding `docs` removes
  its whole subtree. Hidden directories require a literal include prefix, such as `.crew/**`;
  `.git`, application data and symlinked content remain excluded. Filters apply to local roots;
  object-backed roots retain their existing behavior.

## Changed

- **The JVM distribution now requires Java 25.** Native binaries and the Docker image include their
  runtime. Server, frontend and build dependencies have been refreshed, with the supported native
  toolchain pinned to GraalVM CE 25.3.4.1 / JDK 25.0.4.1.
- **Page creation avoids redundant binding writes.** Eligible single-local-root CREATE rebuilds confirm
  unchanged identity bindings in one transaction, retaining atomic validation and normal fallback when
  the durable bindings differ from the expected set. At 3,000 pages, paired JVM measurements improved
  CREATE from 4.74–4.82 seconds to 1.22–1.41 seconds (71–74%); this is a measured workload, not a promise
  for every corpus or concurrent workload. See the [performance summary](../reports/backend-operating-envelope.md).
- **Filters are enforced at access boundaries.** Scans, watches, reads, writes, assets, search,
  identity resolution, proposals and offline commands share the root policy. Physical aliases of the
  data directory and directories replaced with symlinks after scanning cannot bypass the exclusions.
  Excluding a page retains its durable identity and proposal state; reinclusion restores normal
  validation. Hidden content is never used as evidence of deletion or to decide interrupted recovery.
- **Proposals follow configured visibility.** Removing a root hides its retained proposals until that
  root is configured again. Genuinely deleted, eligible pages retain their existing proposal conflict,
  rejection and history behavior. A policy-denied asset upload returns `400 invalid_path`, including
  dot-prefixed filenames that previously failed the route's filename check.
- **Address security predicates are literal-only.** Bind, loopback, and trusted-proxy CIDR checks now
  use strict ASCII IPv4/embedded-IPv4 validation, reject IPv4 zone suffixes, validate `0`–`65535` ports,
  and use Java 25 literal parsing without hostname resolution. Exact loopback aliases and canonical
  IPv4/IPv6 behavior remain.
  Migration: `PLAINBASE_HOST=127.1` is now classified as an exposed bind; the default bind guard refuses it unless
  trusted proxy CIDRs or `PLAINBASE_INSECURE_HTTP` is set. Use `PLAINBASE_HOST=127.0.0.1` for a local loopback bind.
- **Shutdown rejects new work while draining admitted work.** Requests arriving after admission closes receive
  `503 server_shutting_down`; admitted calls, dependent resources and the `DATA_DIR` lock remain owned until the
  ordered shutdown completes. A Git command deadline still records failure, and completion may remain prolonged
  while collaborators finish.
- **Incomplete request bodies are rejected before processing.** When Plainbase detects that a request body ends before
  its declared `Content-Length`, it rejects the body before downstream work and returns `400 invalid_request_body` when
  the connection remains writable. Body-size limits remain unchanged.
- **Search recovers missed retirement updates.** Reconciliation now uses current durable retirement state to remove
  still-retired rows and prevent stale snapshots from reintroducing them, while continuing to preserve unretired
  rows. The admin reindex response's `pages` field now counts accepted snapshot input, excluding retired pages and
  additional carried engine rows.
- **Object mode: throttled GETs retry instead of failing fast.** A 503 or 429 on a mirror GET (the
  hydrate and poll paths) now backs off and retries up to three times with jitter. A persistently
  throttled object can take about two minutes to fail instead of failing immediately; a throttled
  LIST and the streaming bundle-restore GET keep their fail-fast behavior.
- **Object mode: the hydrate memory bound counts bytes actually received.** Chunk packing previously
  trusted the listing's declared sizes; the budget is now enforced over fetched bytes, an object that
  would overrun it is deferred and re-packed into a later chunk, and a single response's initial
  allocation is clamped so a misdeclared `Content-Length` cannot balloon memory up front.
- **Last-root removal preserves backup evidence.** `plainbase root remove` exits `1` before unlinking when any
  `roots.conf.bak` entry exists, including a directory or symlink; the live file and backup entry remain, and the
  command prints an actionable deliberate-resolution error without success/consequence lines. Startup's existing
  warning and damaged-file classification still recognize only regular backup files.

## Removed

- **The windows-x64 native asset is no longer published.** The supported Windows path is WSL2 with
  the linux-x64 binary; the best-effort native Windows build (and its recurring red X on release
  runs) is retired, and no `.bat` launcher ships in the archives.

## Internal

- Backend indexing, runtime lifecycle, configuration and shared transport contracts have clearer
  ownership boundaries. MCP construction now takes narrower dependencies; this is not an MCP
  protocol-version upgrade.
- Gradle test infrastructure moved into `buildSrc`, and shutdown/concurrent-test structure was
  simplified. Release and CI verification continue to cover the JVM distribution and native binaries.
- The cloud-startup budget drill now keeps its per-run boot logs and fails unless every cold run
  shows a complete hydrate and every warm run fetches nothing, so a throttled partial hydrate can no
  longer certify a bogus timing.
- Shutdown guidance now documents the late-hook signal window, ordered final-call draining and
  `DATA_DIR` lock retention. The five-second CIO allowance includes the three-second grace; a separate five-second
  application-disposal allowance gives the ten-second configured-wait forecast, while actual completion can outlast it.
  Supervisor grace must be derived from the workload.
- Docker/Compose, Kubernetes and systemd guidance now distinguishes supervisor deadlines from
  Plainbase completion waits, including the risk of truncated in-flight backup work after forced
  termination. Root local-dev Compose and deploy/proxy Compose remain separate standalone stacks.
- The shutdown example now includes one measured Git-disabled LOCAL workload: 32 valid-ID pages at
  4,096 bytes each, a same-size authenticated PUT, a 1,026 ms owner `H+W+R+D` aggregate, and a
  1,046 ms outer parent signal-through-post-exit-checks observation used for supervisor sizing.
  The 20 ms residual is derived, not a separately measured phase. It is explicitly a single observation with a
  500 ms margin rounded once to 2 seconds; remote OBJECT capacity inputs remain provisional.
