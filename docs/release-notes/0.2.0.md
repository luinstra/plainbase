Three feature families land in this release: an S3-compatible object-storage backend, multi-root
document directories served by one process, and a rebuilt absence-authority model that stops the
server from ever reporting a page as deleted on evidence it does not have.

## Breaking changes

**Roots own top-level URL segments.** A page URL is now `/{root}/{path}` rather than
`/docs/{root}/{path}`, and the primary root is named `docs`. So a primary-root page at
`guides/intro` is `/docs/guides/intro`, and an extra root's page is `/handbook/notes/x`. There is no
redirect from the previous shape. Permalinks are likewise rooted: `/p/{root}/{id}`.

**Root names are stricter, and some top-level segments are reserved.** A root name is lowercase,
2 to 32 characters, must lead with a letter, and allows only single internal hyphens (no trailing or
doubled hyphen). A name that would parse as a page id is also refused. Reserved segments are rejected
at registration (config validation and `plainbase root add` alike), not at read time.

**Delete `DATA_DIR` and reindex after upgrading.** Every derived row carries the root name, and the
primary root was previously stored as `main`. Nothing migrates those rows. `DATA_DIR` also holds
`plainbase.conf` and `roots.conf`, so copy those aside first: deleting the directory is a factory
reset, not a free reindex.

**An unverified absence answers 503, not 404.** When the durable index knows a page the content
store cannot produce bytes for, the read answers `503 absence_unverified` instead of claiming the
page is gone. A 404 is now reserved for a page the index genuinely does not have, and a retired
binding answers `410` with its last-known path. Clients that treated every non-200 as "deleted"
need to tell these apart.

## Added

**Object-storage backend (ADR-0010).** An S3-compatible bucket can act as the content authority,
with a local mirror, git-over-mirror history, and bundle-based disaster recovery. Opt in with
`storage.backend=object`; the default stays `local`. Object mode cannot be combined with a `roots {}`
block in this release.

**Multi-root document directories (ADR-0011).** One process serves N roots on one port, each with
its own editable and history policy, plus `plainbase root add|remove|list`. Adding a root still
requires a restart to apply, and the CLI says so rather than pretending otherwise.

**Per-root page identity (ADR-0012).** Page identity is keyed by `(root, id)`, so the same id in two
roots is legal rather than a conflict to resolve. The rebuild pass and the adopt pass now share one
owner-consistency predicate instead of disagreeing about who owns a reused id.

**Absence authority.** Delete permission is an explicit proof bound to the observation that minted
it, covering exactly the bindings it licenses. A scan proves the pages it read and nothing more, so
an empty mount, a partial restore, and a genuinely emptied root are no longer indistinguishable.

**`RootTreeDto.primary`** on the wire, so a client reads which root is primary instead of inferring
it.

**CLI output is separated from logs**, so a command's output contract is no longer entangled with
diagnostic logging.

## Fixed

- App-database transactions open with `BEGIN IMMEDIATE`, fixing an intermittent `SQLITE_BUSY`
  failure when creating a page. SQLite skips the busy handler entirely on a deferred read-then-write
  promotion, so the configured timeout was never consulted.
- Password hashing moved out of the app-database write transaction, so a create-user call no longer
  holds a write lock across a deliberately slow hash.
- A cancelled request is no longer logged or reported as a server fault.
- The reference reverse-proxy Caddyfile redirects unauthenticated requests to the identity provider
  instead of refusing them.
