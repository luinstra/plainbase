Plainbase 0.6.0 adds custom themes, per-root discussion controls, and OKF-compatible page creation.

## Added

- **Custom light and dark themes.** Select CSS definitions or Tinted Base16/Base24 scheme files
  with `theme.light` and `theme.dark` in `DATA_DIR/plainbase.conf`. Files can live directly in
  `DATA_DIR` or its `themes/` directory. An optional `DATA_DIR/custom.css` adds partial overrides.
  The public contract has 24 `--pb-theme-*` inputs, including colors, fonts and corner radius.
  See the [custom theme guide](https://github.com/luinstra/plainbase/blob/v0.6.0/docs/theming.md) and [adapted examples](https://github.com/luinstra/plainbase/blob/v0.6.0/contrib/tinted/README.md).
- **Per-root discussion controls.** Set `roots.<name>.discussionsEnabled = false` and restart to
  hide discussion UI and disable access for that root. Existing discussion files and Git history
  remain intact; re-enable and restart to restore access. Discussions remain enabled by default.
- **OKF-compatible new pages.** Ordinary blank and template pages now include concept frontmatter
  with `type: "Reference"`. REST callers can supply a descriptive string `type`; omitting it or
  passing null retains legacy creation. Existing documents are not migrated or certified.
  See [OKF-compatible documents](https://github.com/luinstra/plainbase/blob/v0.6.0/docs/okf-documents.md).

## Fixed

- Wide tables scroll within the reading column and editor preview without covering the outline
  or discussions.
- Shell HTML responses require cache revalidation so upgrades do not retain an old asset graph.
- HEAD error responses no longer send a JSON body that can corrupt the next response on a
  persistent connection.
- Embedded frontend assets now synchronize with the current build, removing stale hashed files.
- Mermaid rendering follows theme changes and supports additional CSS color spaces.

## Before upgrading

- **Move any content root at `DATA_DIR/themes` before upgrading.** This placement, in any letter
  case, now prevents startup and is refused by `plainbase root add`; it previously only warned.
  Other content-root locations inside `DATA_DIR` remain warning-only.
- Custom builds that edited `frontend/src/styles/tokens.css` must move their values into theme
  definitions; that file has been removed. Prefer public `--pb-theme-*` inputs. Private
  `--pb-*` roles remain unversioned; the former `--pb-surface-chrome` role now derives from
  `--pb-theme-muted`, which also feeds inline-code and table-header backgrounds.
- Restart after changing a theme selection; reload the page after editing a selected file.
  Invalid selections, unreadable files and scheme conversion failures fall back to the bundled
  definition for that mode. A declared scheme variant must match its selected mode.
  `DATA_DIR/themes` must be a real directory, not a symbolic link. Raw upstream schemes have
  no contrast guarantee.
- New page names deriving to `index.md` or `log.md` need another title or a custom slug through
  **Edit URL**. Sections and save-as-new recovery retain legacy creation; recovery drops the
  old type and metadata. Later edits remain author-owned.
- Disabled discussion roots return `403 discussions_disabled` for writes and preview, and
  `reason: "disabled_by_config"` for unavailable reads. Tree roots include
  `discussionsEnabled` only when false.

## Maintenance

- Update DOMPurify to 3.4.16 and source-map-js to 1.2.2.
