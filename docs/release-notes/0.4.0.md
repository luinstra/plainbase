Plainbase 0.4.0 adds portable page discussions for people and agents, plus a quieter reading and editing experience.

## Added

- **Page and passage discussions (#54).** Start a conversation about a whole page or selected text,
  reply, and resolve or reopen it. Discussions appear below Page Info by default, with a local
  Hide/Show control. Root inboxes and standalone discussion links remain available.
- **Portable discussion files.** Each editable local root stores its discussions and comments as
  Markdown under `.plainbase/discussions/`. These files are authoritative; the SQLite discussion
  index is derived and rebuilt at startup. External edits are picked up by background reconciliation.
- **Selection-aware composition.** New discussion uses selected page text automatically and shows
  a passage preview for confirmation; without a selection, it starts a whole-page conversation.
  Failed posts retain drafts, and a failed refresh does not turn a confirmed post into a failed write.
- **Discussion lifecycle controls.** Edit or retract comments, resolve or reopen conversations,
  and reattach an open passage discussion after previewing and confirming a fresh selection.
  Original anchor evidence is retained separately. Purge is restricted to admins under enforced auth;
  earlier comment bodies may remain in Git and backups.
- **Agent discussion tools.** MCP adds `list_discussions`, `get_discussion`, `start_discussion`,
  and `add_comment`. REST also exposes anchor preview and lifecycle operations. `PROPOSE` and
  `COMMIT` agents start discussions and reply directly, with visible agent provenance; these writes
  do not enter the page proposal queue. Agents cannot reattach or purge. See the
  [MCP guide](https://github.com/luinstra/plainbase/blob/v0.4.0/docs/connect-your-agent.md) and
  [HTTP agent workflow](https://github.com/luinstra/plainbase/blob/v0.4.0/docs/http-agent-workflow.md#discussions-read-preview-start-and-reply).

## Changed

- **Stable reading layout.** Page Info and stacked discussion cards share a consistent margin.
  Discussion controls are smaller and quieter, secondary actions live in menus that close when focus
  moves away, and unavailable actions explain why on hover or focus.
- **Edit and View in the top bar.** Switch between reading and editing from the same position.
  View asks before discarding unsaved body or metadata changes.
- **Clearer Mermaid diagrams.** Nodes use distinct fills, borders and subtle dark shadows, with
  lighter blocks in dark mode.
- **Rendered source ranges.** Page HTML carries `data-pb-src` half-open UTF-8 byte ranges on
  rendered Markdown blocks for passage selection. HTML comment blocks now render inside a `<p>`
  carrier, which can affect layout.

## Before upgrading

- **Check reserved names.** Rename any root named `discussions` in its declaring `plainbase.conf`
  or `DATA_DIR/roots.conf` before upgrading; the new version refuses that configuration, including
  when running `root remove`. Root-level `.plainbase/` is also reserved (NFC-normalized and
  case-insensitive). Remove or revise includes whose first literal-prefix segment is `.plainbase`;
  wildcard includes cannot expose the collection. See
  [configuration](https://github.com/luinstra/plainbase/blob/v0.4.0/docs/configuration.md#discussions-support-and-authorship).
- **Include discussions in backups.** Back up each root's `.plainbase/discussions/` collection and
  Git history. `DATA_DIR` alone cannot recover comments. `DATA_DIR/discussions.db` and its sidecars
  are derived state and need no backup.
- **Know the authorship mode.** Uncredentialed `auth.mode=off` uses one shared Anonymous identity,
  with ownership bypass and local lifecycle actions including purge. Use enforced authentication
  for distinct human identities and role-based permissions.
- **Inspect uncertain writes before retrying.** Source reload alone does not settle an uncertain
  write outcome. See
  [operation and recovery guidance](https://github.com/luinstra/plainbase/blob/v0.4.0/docs/operating-plainbase.md#discussions).

## Limitations

Discussions require editable local roots; read-only and object-mode roots report them unavailable.
Roots added after startup, or unavailable at startup and later restored, need a restart for
discussion watcher coverage. Object-mode Discussions, selection-performance refactoring,
Firefox multirange selection and cached-session 401 redesign remain deferred.
