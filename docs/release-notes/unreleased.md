# Unreleased

- Custom themes select complete light and dark CSS definitions with `theme.light` and `theme.dark` in `DATA_DIR/plainbase.conf`, using files directly under `DATA_DIR`; optional `custom.css` adds partial overrides in both modes. The contract has 24 public `--pb-theme-*` inputs, four required. An invalid selection value warns and uses that mode's bundled definition; an unreadable selected file also serves the bundled definition, while an unreadable `custom.css` serves no override. Restart after changing a selection; reload after editing file contents. A Tinted converter and adapted Base16/Base24 examples are included. See [custom themes](../theming.md).
- Decorative corner radii use a rem-based scale: the default `0.25rem` base is 4px at a 16px root font size, and the seven fixed multipliers retain their default measurements at that root size. See [radius settings](../theming.md#radius).
- Upgrading custom builds: `frontend/src/styles/tokens.css` has been removed. Advice: Move custom values into a theme definition and prefer public `--pb-theme-*` inputs. Compatibility policy: Private `--pb-*` roles are unversioned. The 0.5.0 `--pb-surface-chrome` role now derives from `--pb-theme-muted` in the generic layer; that input also feeds inline-code and table-header backgrounds in the generic layer. See [the theme contract](../theming.md).
- Discussions can be disabled independently with `roots.<name>.discussionsEnabled = false` (default-on, applied after restart). Disabling hides discussion UI and preserves files and Git history; re-enabling and restarting restores access. Known disabled roots return `403 discussions_disabled` for writes/preview and `reason: "disabled_by_config"` for unavailable reads; tree roots carry an optional `discussionsEnabled` flag, omitted when true. See [per-root discussion access](../configuration.md#per-root-discussion-access).
- Wide tables scroll within the reading column and editor preview, keeping the outline and discussions clear while preserving every column and keyboard access.
- Ordinary new-page creation now emits OKF-compatible concept frontmatter with `type: "Reference"` for blank and template pages. REST callers can supply an optional descriptive string `type`; omitted or null keeps legacy creation. Typed title/slug/type reject control characters, U+2028/U+2029, U+FFFE/U+FFFF, and lone surrogates, and typed body rejects lone surrogates. Names deriving to `index.md` or `log.md` require another title or a custom slug through **Edit URL**. Sections remain legacy; all save-as-new recovery remains legacy and drops old type and metadata. Existing documents and later edits are author-owned, and no content directory is certified or automatically migrated. See [OKF-compatible documents](../okf-documents.md).
