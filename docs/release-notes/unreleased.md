# Unreleased

- A new reader profile serves content anonymously and read-only. Select it with `PLAINBASE_PROFILE=reader` or `profile = reader` in `plainbase.conf`; either source enables it and neither can turn it off. Editing, Git history, discussions and login are off, `plainbase adopt` refuses to write, and `GET /api/v1/session` reports `auth_mode: "reader"`. Readers bind to loopback only, behind a tunnel, answer HEAD like GET on every mounted URL (at the same cost) and do not support OPTIONS. The documented deployment reads an immutable S3-compatible release prefix taken only from `PLAINBASE_S3_PREFIX`, with an R2 token holding Object Read; the session then also reports the release label from the prefix. An object-backed reader finishes a strict hydrate and a complete first index before serving, or it refuses boot; every start, including a retry, needs a fresh DATA_DIR holding at most `plainbase.conf` and `plainbase.lock`, so custom theme files cannot be used there; and it does not poll the bucket after boot. Several object readers may share one prefix; their answers agree only when every page has a unique, valid frontmatter id, and a reader logs a warning that counts pages with a missing, malformed or duplicated id and names up to five of them. A reader can also serve local roots, which keep their DATA_DIR and pick up file changes. See [the public reader guide](../deploy/public-reader.md).
- Reader pages: the first HTML response carries the rendered article, a `plainbase-page-id` meta tag and an escaped title and description. Optional file-only keys `site.canonicalOrigin` (adds a canonical link) and `site.name` (the initial title suffix) are available. Aliases and landing children redirect in one hop to the URL that owns the page; a landing child whose folder URL belongs to another page or alias serves at its own URL. Misses return the shell with 404 and unavailable content with 503, and every reader response sets Cache-Control, with a one-year immutable lifetime for hashed bundle files and `no-store` for `/healthz`. In the browser app, a reader shows no editing, creation, review, administration or discussion controls, workspace-only addresses show not-found, and the address stays where the server put it, apart from a non-canonical page spelling such as a trailing slash, which is replaced once with the canonical URL. Workspace caching is unchanged. See [pages, statuses and caching](../deploy/public-reader.md#pages-statuses-and-caching).
- Compatibility policy: Configuration loading is stricter in every profile, workspaces included. A directory, a dangling symlink or an unreadable file at `DATA_DIR/plainbase.conf` now refuses, where it previously loaded defaults; a symlink to a regular file is still followed. These previously ignored settings now refuse too: a `profile` key other than a literal `workspace` or `reader`, case-insensitive (including a `${...}` substitution), an invalid `site.canonicalOrigin` or `site.name`, and any non-blank `PLAINBASE_PROFILE` other than `reader`, `workspace` included. Advice: Before upgrading, make sure `plainbase.conf` is absent or a readable regular file (or a symlink to one), and remove or correct those keys and that variable.
- Object storage, every profile: a scan whose mirror walk was incomplete, for example after skipping an unreadable entry, no longer counts as evidence that pages were deleted. The pages it missed keep their identity until a complete scan confirms their removal; until then, reads of them can return 503.
- Workspace browser app: the new-page, editor, history, review, administration and discussion controls and addresses now wait until the session is known, or until the session endpoint returns 404 for an auth-off workspace. If the session cannot be determined, those addresses show an error with a **Retry session** button. A failed session refresh keeps the established mode, so an open editor keeps unsaved edits through a reconnect. A folder URL with a trailing slash or decomposed Unicode now shows the folder, highlighted in the sidebar and usable for new pages, instead of not-found. Reload the page after changing the server's authentication mode.
